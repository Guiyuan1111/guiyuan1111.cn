# v1.0.4（2026-09-27）

基于 v1.0.3 的 P1 级性能优化五项落地（多子代理分析 + 执行，性能分析报告 P1 全清）。

## 变更

- **图片管线收敛**（P1）：14 张内容源图统一收敛到 1600px（原 5088px/3000px 直出）；远程图床（image.radishzz.cc）6 张大图下载本地化至 `src/content/posts/_images/` 并改相对引用，构建不再依赖外网图床；`remotePatterns` 收紧 hostname 白名单（原先允许任意 https 外链图进构建管线）
- **移除无效字体预载**（P1）：STIX-VF/STIX-Italic-VF 仅被 markdown 装饰元素引用且默认 sans 模式用不到，每页 112KB 预载移除（Head.astro 内注释保留恢复方法）
- **CSS 按页分割**（P1）：markdown/comment/extension 三个仅文章页需要的样式从全局 Layout 下沉到 posts/[slug]、about、index（首页摘要块用 .heti），全局 Layout.css 124KB → 95.5KB
- **CI 缓存**（P1）：GitHub Actions 增加 astro-og-canvas 与 Astro 内容层两个缓存步骤，CI 冷构建预计省 5-10s
- **多语言文章归档**（P1）：45 篇未启用语言（en/es/ja/ru/zh-tw）的文章用 git mv 归档至 `src/content/_archive/`（保留历史与目录结构），不再进入 markdown 构建管线；恢复方法已更新至 [note/disabled-features.md](../disabled-features.md)

## 性能（实测）

- 产物内容图片 10.44MB → **2.81MB（-73%）**；最重的 markdown-extended-features 页图片载荷 7.5MB → ~2MB
- 构建 18 页 / astro build 25.23s（热缓存）；KaTeX 页与全部 zh 内容正常；LQIP 随新文件名自动重建 14 条
- 非文章页 CSS：全局样式减重 28.5KB raw + 每页字体预载减 112KB

## 关于"转 webp"的结论

webp 转换本来就在发生（Astro 构建默认输出 webp），此前的问题不在格式而在分辨率未收敛（3000-5088px 源图全尺寸直出、无 srcset）。本次以"源图收敛到 1600px"解决；Astro 响应式图片（image.layout）经调研暂缓启用——dist 产物会膨胀 9 倍变体数且与主题样式有冲突风险，待移动端优化需求明确后再评估。
